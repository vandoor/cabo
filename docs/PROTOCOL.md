# 联网与状态边界

## 客户端消息

- `join({name?, token?}, ack)`：首次昵称入座；重连使用 token。成功返回 `{ok:true,token,view}`。凭证仅通过本连接确认发回，不出现在广播、日志或其他玩家视图。
- `sync(ack)`：已验证身份主动获取当前完整个人视图。
- `command({requestId,version,command}, ack)`：类型定义见 `packages/game/src/types.ts`。返回 `{ok,error?,view?}`，错误含 code/message。必须从最新视图取版本；失败后显示原因并重新选择/确认。
- 服务端 `state(view)`：针对每个连接分别构造。`takenOver` 告知被新连接接管；`removed` 告知大厅席位被移除。

每个事件同步执行，入口只读取一次时钟。先处理该时间之前的超时，再校验身份、请求格式、去重、版本和规则。游戏状态版本统一由房间层管理，事件处理内所有投影使用同一时间，避免截止时刻跨越校验和执行。

每个身份缓存最近 256 个请求 ID 的操作结果；缓存不保存旧视图。重复请求返回原操作结果和**当前**个人视图，避免重播过期私密牌面。更老请求携带的旧版本会被拒绝。客户端超时可使用同一请求 ID 重试一次，之后同步完整状态。服务器重启清空会话和去重缓存。

Socket.IO 默认不保证断线期间的消息重发，因此重连不依赖消息补发，而是重新验证身份和获取完整视图。参考 [Socket.IO 投递保证](https://socket.io/docs/v4/delivery-guarantees/)。

## 牌面过滤

暗牌只包含 `{index,public:false}`，没有真实牌 ID、点数或花色；自身暗牌也不例外。失败公开牌、弃牌堆取回后留在手中的牌和轮末手牌带 `card`。待处理 `pending` 只出现在当前玩家视图。弃牌堆来源另用公共字段 `publicDraw:{actorId,card}` 展示正在取回的牌，所有玩家及观战者可见，操作完成后移除；摸牌堆来源不生成该字段。开局/技能 `reveal` 只发给获准玩家，包含绝对截止时间，过期后删除；前端同时按截止时间隐藏，断线立即隐藏查看遮罩。正常手牌总分只在结算时公开。

公共日志只记录动作，不记录私密点数。前端仅 localStorage 持久化身份 token，不持久化游戏视图或牌面。浏览器使用原生 JSX 转义昵称。生产无测试场景控制接口。

## 换牌位置提示

成功处理 `swap` 后，仅操作玩家的 `PlayerView` 可包含 `swapFeedback: {outcome,index,deadline}`。`outcome` 为 `swap-success`（单张）、`merge-success`（多张同点）或 `merge-failed`（多张不同点）；`index` 为从 0 开始的最终位置，成功取所选最小序号，失败取追加后的末尾。字段不包含牌面或真实卡牌标识，命令格式保持不变。

`deadline` 是交换完成时间加 5000 毫秒的服务端绝对时间。广播、同步、重试、刷新均不重新计时；过期不再返回，前端同时按服务器时钟偏移隐藏提示。后续 J/Q 技能换走该位置时清除受影响玩家的提示，结算、大厅、新轮也不保留。被拒绝的操作不会生成新提示。

前端仅给自己的新牌显示金色边框、“新换入”和结果位置文案；摸牌堆来源仍为暗牌，弃牌堆来源为明牌。落位强调只播放一次，普通状态更新不重播；减少动态效果偏好关闭动画，但保留边框与文字。

## 生命周期

房主转移按入座顺序选在线玩家；全部离线暂保首个席位作为可恢复房主。大厅全离线 60 秒清理，活动对局不因离线删除。房间容量 4，昵称 1–24 字符，消息上限 8 KiB；连接内 join/command 限流 100 次/10 秒。首发设计用于可信局域网，未提供互联网账号系统或持久化数据库。


## 任意位置交换与技能提示（2026-10-09）

7–10 沿用 `skill {targetId,index}`。J/Q 使用 `exchange {first:{playerId,index},second:{playerId,index}}`，两张牌分别指定玩家和从 0 开始的位置；可选自己和对手，也可选两名对手。两名玩家必须不同，两处都必须有牌；无需相同序号或相同手牌数量。旧的 J/Q 单位置 `skill` 请求被拒绝，不隐式补选位置。

服务器验证当前回合、牌堆来源、J/Q、玩家和位置后一次性交换，公开状态跟随牌移动，清除各自被移动位置的 `swapFeedback`。校验失败不交换、不弃置待处理功能牌，客户端可重新选择。交换不新增私密揭示。

成功使用技能时，公共日志增加 `SkillAnnouncement`：7/8 与 J/Q 为 `skill:{actorId,kind}`，`kind` 为 `peek` 或 `exchange`；只有 9/10 为 `skill:{actorId,kind:"spy",targetId,index}`，`index` 从 0 开始，不含被查看的牌面。9/10 向所有玩家（包括操作者）及观战者显示“甲查看了乙的第3张牌”；7/8 与 J/Q 保持仅向其他玩家和观战者显示“某某 发动了偷看／交换技能”。所有提示使用日志的服务端时间 `at + 5000` 到期。刷新不会延长展示时间；立即进入结算或终局时仍显示至原截止时间，返回大厅后不显示。


## CABO 持续提示（2026-10-09）

客户端直接使用现有 `caboCallerId` 和 `remainingFinalTurns`，无新增协议字段。仅在 `turn` 阶段有人呼唤 CABO 时，所有玩家在顶部固定区域看到呼唤者、剩余行动人数和“其他玩家各完成一次行动后结算”。状态随服务端更新，刷新和自动重连后恢复，结算、终局、大厅或新轮不显示。

CABO 与技能提示共用 `TableNotices`：CABO 在上，技能提示在下；使用固定预留区域稳定页面布局。通知高于错误/断线提示、低于确认和私密查看弹窗，不拦截点击；技能提示仍使用原服务端截止时间。有呼唤者时操作区改为最后行动阶段提示，已禁用的 CABO 按钮显示“已有玩家呼唤 CABO”。


## 观战订阅与角色

`PlayerView.role` 为 `player`，`SpectatorView.role` 为 `spectator`，公共客户端类型为 `RoomView`。`watch({requestId}, ack)` 无需昵称或 token，在大厅及任意对局阶段均可订阅；ACK 返回 `{ok, view}`，后续通过 `state` 推送公共状态。`unwatch({requestId}, ack)` 取消推送。`sync({requestId}, ack)` 按当前连接角色返回视图，兼容旧的 `sync(ack)`。

公共投影直接从引擎状态生成，再单独向玩家投影附加私密字段。观战数据含玩家和手牌数量、公开牌、弃牌顶、弃牌堆来源的 `publicDraw`、deckCount、行动者/截止时间、CABO、公开技能日志和结算；不含 `selfId`、`initial`、`pending`、`reveal`、`swapFeedback`，暗牌只含序号和公开标志。观战连接不占席位、不影响准备判断、房主迁移或离线大厅清理；发送游戏命令返回 `SPECTATOR`。观战连接即使取消订阅，也不能原地切换为玩家。

浏览器用 URL `?watch=1` 保存观战模式，重连优先 watch，不使用或覆盖 localStorage 中的原玩家 token。退出后建立新的访客连接返回首页；需要主动重新入座，或刷新恢复原玩家身份，无观战页面直接转玩家控件。

## 响应计时

客户端和服务端分别用 `performance.now()` 计算相对耗时，以 `requestId` 关联，不能直接相减两端时钟。日志前缀 `[cabo-timing]`，JSON 字段为 `side,step,phase,durationMs,result,requestId`（旧客户端无 requestId 时服务端省略它）。不记录 token、昵称、命令参数、牌面或完整状态。

客户端网络操作记录 `start/send/ack/commit/paint`，重试额外记录 `retry`；纯本地选牌记录 `start/commit/paint`。`commit` 在 React layout effect 中采集，`paint` 是提交之后双 requestAnimationFrame 的绘制机会测量，不等同于显示器硬件呈现。服务端 `handle` 是同一请求处理至响应就绪的耗时，失败及去重命中均记录。日志使用异步输出，不在操作路径等待采集完成。客户端自动命令重试仍沿用相同 requestId；验收命令本身不重试。

倒计时仅更新子组件显示秒数，父牌桌只在状态、交互或各私密提示截止时更新；首页不运行牌局计时器。8 秒结算冷却与服务端超时保护不变。


## 公开取牌与 CABO 计分更新（2026-10-09）

弃牌堆取牌通过独立公共投影展示，不放宽 `pending` 的私密过滤。单张交换、同点合并成功以及失败追加均把弃牌来源的新牌置为 `public:true`；摸牌堆来源仍为 `false`。公开状态随 J/Q 交换移动，不附着于旧位置；后续弃置或替换按正常规则移走该牌。刷新从当前状态恢复公开待处理牌和手牌明牌，不延长技能提示。

CABO 呼唤者并列最低仍为 0；失败改为手牌分加 10，例如 23 → 33。恰好 QQKK 的特殊计分优先；首次累计恰好 100 降为 50、之后恰好 100 不重置、超过 100 终局的规则保持不变。
