## 后续发版约定

1. 完成实现及验证，提交源码；记录验收命令、结果和限制。
2. 以明确的源码提交构建并部署，保留旧构建、校验值及部署记录。
3. 部署验证通过后，为该提交创建附注标签，说明变更、验证结果和源码提交号，并将提交及该标签推送到远端。
4. 更新本页版本表；文档补记可以是独立提交，发布标签仍指向构建实际使用的源码提交。

这是发版操作约定，目前没有自动打标签或自动创建 GitHub Release 的流水线。

## 查看、取出和打包

```bash
# 获取远端版本标签
git fetch origin --tags
git tag --list 'release/*'

# 查看指定版本
git show 'release/2026-10-09-a31f429'

# 在新目录取出旧版本，不切换或覆盖当前运行目录
git worktree add --detach ../cabo-history-1249a9a 'release/2026-10-09-1249a9a'

# 导出该版本已跟踪的源码文件
git archive --format=zip --prefix=cabo/ --output=cabo-1249a9a.zip 'release/2026-10-09-1249a9a'
```

Git 标签归档的是源码、锁文件、测试和跟踪的资源；不包含被忽略的依赖、构建产物、测试日志，也不包含内存中的牌局。精确恢复旧运行构建使用部署备份；从标签重新构建按对应版本的 README 操作。Git 标签本身不会重启服务或恢复历史牌局。

部署备份保存在服务器本机 `artifacts/deployments/`，未上传至 Git。2026-10-09 的 `20261009T114249Z` 目录保留部署前构建、校验记录、完整源码 bundle 和 `ROLLBACK.txt`；回滚运行构建不会自动改动 Git 分支。
