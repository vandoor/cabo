# CABO · 林间牌桌

最多四个独立房间、每间 2–4 人的局域网 CABO 游戏。一个人启动服务，大家用手机或电脑浏览器打开同一个地址入座或观战。深绿牌桌、中文交互、服务端判定和私密牌面过滤。

## 启动

需要 Node.js 22.12+（本次验证使用 25.8.0）和 npm。

```bash
npm install
npm run build
npm start
```

默认监听 `0.0.0.0:3000`，网页和 Socket.IO 共用端口。启动时打印本机和网卡地址；本机打开 `http://localhost:3000`，其他设备打开 `http://<服务器局域网IP>:3000`。可通过 `PORT=3001 npm start` 换端口。保持终端运行，Ctrl+C 停止。

首页创建房间后自动成为房主，朋友从列表选择加入或观战；2–4 人全部准备后开始。每人选择两张牌并确认查看，记住后盖回。正常回合依次选择摸牌/取弃牌堆，再弃置、换牌或使用技能；也可在抽牌前呼唤 CABO。结算至少展示 8 秒后房主开始下一轮。终局可以重新开场。

开发模式：`npm run dev` 同时启动后端 3000 和 Vite 5173，打开 `http://localhost:5173`。Vite 代理实时连接，不需要配置跨域地址。

## 规则与交互

- 实际牌组 52 张：四花色 A–Q、黑桃/红桃 K、大小王各一张。A=1、J=11、Q=12、K=13、大小王=0，花色不参与判定。
- 每人 4 张暗牌。开局 30 秒选择两张，超时保留服务端已确认的单张选择并从左补齐；最多查看 10 秒。选择第二张后按“查看选中的两张牌”确认；未确认的双选仍为本地草稿。
- 每回合 60 秒。单牌交换必成功，多张同点才成功；新牌放最小序号，其余位置压紧。失败则所选旧牌原位公开，摸到的牌追加至末尾；摸牌堆来源暗置，弃牌堆来源保持明牌。手牌数量不限。
- 弃牌堆取回的牌立即公开，单张换牌、合并成功或失败追加后都保持明牌。J/Q 交换时公开状态跟随牌移动；此牌离开手牌后不再保留原位置的公开状态。摸牌堆抽牌仍仅本人可见。
- 摸牌堆的 7/8 看自己一张，9/10 看对手一张，J/Q 交换任意两名不同玩家各一张牌（自己与对手，或两名对手），双方序号不限。查看最多 5 秒，且不超过回合剩余时间；交换不揭示暗牌，公开状态随牌移动。弃牌堆取牌不能发动技能。9/10 向所有玩家与观战者提示被查看的玩家及位置，不公开牌面；7/8 向其他玩家提示技能；J/Q 向所有玩家（包括发动者）与观战者显示交换双方的玩家和牌位。提示按服务端时间显示 5 秒，刷新不延长。
- 抽牌前呼唤 CABO，占用整个回合；其他玩家各行动一次。所有玩家顶部持续显示呼唤者和剩余行动人数，滚动或重连后仍可见，直到本轮结算。呼唤者并列最低得 0，否则手牌分加 10（如 23 → 33）。摸牌堆抽尽时完成当前回合后直接结算，不重洗。
- 恰好 QQKK 为“神锋特工队”：自己 0 分，其余各 50 分，优先于 CABO。各人每场首次累计恰好 100 分重置为 50；之后有人超过 100 则终局，累计最低者获胜，可并列。
- 首轮随机首家，以后按座位轮换。超时未抽则自动摸牌并弃置，已抽则弃置，不使用技能。
- 手机上自己的牌和操作优先显示；对手区域可切换玩家。点位置后明确确认，无需拖拽、悬停或右键。

## 重连与房间

首次创建或加入前，浏览器使用安全随机数生成并持久化身份及待完成请求。刷新与断网后自动查询原会话、恢复原席位；首次确认丢失也不会新增席位。恢复凭据每次绑定轮换，旧页面被接管后停止自动恢复，需点击“主动接管”。网络超时、临时限流以 1、2、4、8 秒封顶重试，保留身份；游戏操作断线期间不排队重放。

首页显示最多四个房间的名称、房间号、人数、房主、阶段及观战人数。创建者成为房主，第五间由服务器拒绝。每个浏览器身份最多一个席位；进行中返回列表或观战别房时保留原席位，可用“返回我的牌局”恢复。大厅返回列表会离座，进行中须结束整场回大厅并离座后才能加入别房。

玩家页面使用 `/?room=<房间号>`，观战使用 `/?room=<房间号>&watch=1`，URL 不含凭据。观战不占席位，也不接收私密查看、待处理摸牌或个人换牌反馈。浏览器前进/后退按相同流程切换。所有玩家离线满 5 分钟关闭房间，期间照常计时，观战者不会延长保留时间；最后席位离开立即关闭。房主可以二次确认关闭房间；“结束整场”仅返回本房间大厅。

恢复限同一浏览器、同一访问地址。存储不可用时不能入座，仍可观战。旧版单房间凭证失效；服务器重启、清空存储或更换访问地址后不能按昵称认领旧席位。所有牌局与积分保存在单进程内存中，不提供服务器重启后的牌局持久化。

## 验证

本地快速验收（安装和构建在计时之外）：

```bash
npx playwright install --with-deps chromium
npm run build:acceptance
npm run accept
```

`accept` 使用已构建产物，全流程 60 秒硬上限，无自动重试。运行核心规则和真实 Socket.IO 测试，以及单组 Chromium 实际点击流程；浏览器单项 35 秒上限。其他玩家由真实 Socket.IO 客户端准备。失败输出当前步骤，清理本次启动的进程。日志和 trace 位于 `artifacts/acceptance/`，每次运行前归档旧证据。

可选检查：

```bash
npm run test:timing  # 超时、到期、离线等待、冷却规则（模拟时钟）
npm test             # 全部规则及联网测试
npm run test:e2e -- --project=chromium-desktop --grep-invert one-minute
# 完整跨浏览器矩阵需另外安装 WebKit；不作为一分钟验收条件
npm run check
```

浏览器测试通过独立的 3100 端口进程运行，不修改 3000 端口上的真实牌局。测试用的确定性洗牌和特殊场景路由仅存在于 `tests/e2e/server.ts`，不打入生产服务。

测试报告：`playwright-report/index.html`；失败 trace：`test-results/`；牌桌截图：`artifacts/table-*.png`。当前 WSL 无 sudo 的浏览器依赖处理方法与实测边界见 [验收记录](docs/VALIDATION.md)。

## 项目结构

```text
packages/game/src/   共享协议、独立规则引擎、确定性规则测试
apps/server/src/     RoomManager、独立房间、会话、个人视图、计时与联网测试
apps/web/src/        React 响应式牌桌
apps/web/public/     54 张 SVG 牌面、牌背、阶段图标
scripts/            素材生成、开发和浏览器测试启动器
tests/e2e/          Chromium / WebKit × 手机 / 桌面
```

`npm run assets` 可重新生成素材。保留完整 54 张素材，游戏只采用上述 52 张。
